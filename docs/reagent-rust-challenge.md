# Rust self-migration challenge contract

This is the task-specific adapter to the autonomous-task rules in `docs/reagent-v0-design.md` §3. It does not add a Rust mode to the baseline harness or authorize a trial now. After the prerequisite issues land, pin the controller and migration-target commit IDs in the launch record; “its own codebase” means the target at that pinned revision, not the older roadmap assessment. The controller must not modify the protected Go reference or evaluator.

**Objective and scope.** In one submitted prompt, discover requirements from the pinned Go source, tests and documented behavior; port meaningful tests before substantive implementation (minimal API stubs are allowed), then port the implementation. Fully converted means the Rust executable replaces the Go runtime, CLI, provider adapters, file/workspace/process tools and terminal behavior in scope at the pinned target. Port the behavior-focused tests and Rust build/CI for that implementation. The Rust binary, not a wrapper around the Go reference, must pass scripted-tool and local fake-provider round trips. Treat deliberate behavior changes, known Go bugs and disagreements between specification and code explicitly; old behavior is not automatically the requirement.

**Boundary of conversion.** Keep repository history, licenses, documentation, icons/assets and existing Python benchmark/evaluation tooling as inputs or external evaluators rather than translating them to Rust. Benchmarks that launch the agent must be adapted to the Rust binary and retained as executable checks; they must not secretly substitute Go. Use a pinned stable Rust/Cargo release and a checked-in lockfile for the candidate. Permit only crates needed for the existing capabilities (for example JSON, HTTPS and terminal input); declare and lock dependencies in the candidate, not in the baseline agent. Run Linux x86-64 CI and macOS arm64 local checks for the pilot/trial; report other platforms as unsupported or unverified, never silently count them as passed. Pin exact toolchain, dependency graph, supported-platform commands and available toolchains at the pilot before the full trial.

**Gates and evidence.** Discover requirements and map each preserved behavior to Rust tests or an explicit gap; the complete map, architecture and translated suite are outputs of the run, not prepared solutions. Fix a tests checkpoint before implementation. At that checkpoint and again on a fixed implementation checkpoint, obtain at least two fresh independent reviewers with the task/spec, identical approved snapshot and factual evidence, but no author reasoning or sibling reviews. Record each finding and its disposition; rerun affected checks on the changed snapshot. Final verification includes Rust build/tests, behavior comparison against the protected reference, scripted tools, local fake-provider round trips and the declared terminal/CI checks. Keep the candidate tree including staged and untracked files and exact commands, outputs, skips and failures. No required failed/skipped check, missing evidence, exhausted budget or unresolved difference can be reported as verified success.

The pilot in #54 must exercise the general baseline on an ordinary behavior-preserving refactor too, then force a continuation on the small Rust challenge before any separately authorized full self-migration. Execution-time model access, budget, writable workspace and publication permissions require explicit authorization; this document grants none.
