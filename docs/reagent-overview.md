# re:agent — how it works today

This describes the code as it is. It does not decide what re:agent may become: nothing here rules a feature in or out. If this page and the code disagree, the code is right and the page should be fixed. The longer specification it replaces is kept in `docs/archive/` for history only.

## Shape

One Go binary, `cmd/reagent`, over one package, `internal/reagent`. It talks to providers over plain HTTP (OpenAI Responses and Anthropic Messages, no SDKs), uses native function tools, and keeps the complete history locally, with each provider's native items preserved so its own conversation continues exactly.

- `reagent run "prompt"` does one task; `reagent chat` holds a conversation.
- A **Session** holds what outlives a run: configuration, the accepted transcript, every call ID, workspace grants. A **Run** is one user turn's loop: request, accept the response, dispatch its tool calls in order, repeat until the model replies without tools.
- Runs end with a distinct status: completed, refused, cancelled, provider error, incomplete response, protocol error, limit exceeded, effect unknown, tool internal error, persistence error. `completed` means the model replied, not that the task succeeded.
- After completed or refused, the session continues. A provider error or cancellation before a response was accepted is marked `resumable` and the next message carries on. An exec timeout goes back to the model to inspect. Other outcomes block the chat until `/reset` or `/compact`.
- Budgets (`--max-steps`, `--max-tool-calls`) are off by default. An accepted tool call is never run twice and never retried automatically.

## Tools

| Tool | What it does |
|---|---|
| `list_files`, `read_file`, `search_text` | Read the active workspace; results fit a 32 KiB budget and say when they are incomplete |
| `edit_file`, `write_file`, `delete_file` | Guarded text edits, creation and deletion; opt-in recursive deletion |
| `git_inspect` | Read status, staged/committed diffs, raw worktree diffs, historical files and logs in every mode, without configured programs or network; partial clones are refused |
| `exec` | Run an argv (no shell) with a timeout, optionally chained with `then` |
| `recall` | With `--context-gc`, retrieve a dropped tool outcome by its original call ID, in every mode and for agents |
| `request_workspace_access`, `switch_workspace` | Ask the human for another root, and move to it |
| `spawn`, `send`, `wait`, `threads`, `cancel`, `dismiss`, `reset` | With `--agents`: concurrent agents with per-spawn read/write authority, operated only by their parent |
| `report_friction` | With `--report-friction`: let the model report harness friction |
| `git_do` | With `--git-do jev\|recipe`: run one of twelve fixed git recipes and return proof |

Paths stay inside the active root and skip `.git`, `.env` and `.env.*`; these are ordinary checks, not a sandbox, and `exec` is not bound by them. `--read-only` withholds the writers and `exec`; plan mode refuses them at dispatch.

**Files.** Reads are capped at 1 MiB and requests at 10 MiB. Writers check an optional `expected_sha256`, or the last digest that conversation saw. With agents enabled, file-tool checks and publication share a tree-wide guard; observations remain local, and deleted observed files require an absence read before recreation. Exec and external editors do not participate. `edit_file` supports exact replacements, `edits`, `replace_all` and `append_text`; near misses report candidate lines rather than fuzzy-applying. Explicit digests let `delete_file` stream-hash large binaries; `recursive:true` deletes trees without following symlinks and reports actual removals, including partial failure.

**git_inspect.** `status` separates staged changes (base → index), unstaged changes (index → raw worktree) and untracked paths. `worktree_diff` compares raw files, including untracked additions, to `rev` (default `HEAD`); both accept literal `paths`, and `worktree_diff` accepts `stat:true`. `diff` with `staged:true` compares `from` (default `HEAD`) to the index, without `to`. Go hashes raw files using the repository's object format, never follows symlink content or descends into gitlinks, and reports special index flags as unknown comparisons. Conversion attributes/config are marked “comparison not filter-aware.” Attribute lookup uses one NUL-delimited stdin request, not per-file batches. Bounded deterministic Myers diffs use three context lines; pure additions/deletions render directly without the search-distance cap. Binary, oversized or over-budget inputs show sizes/blob IDs instead. Narrow truncated results with `paths`; unavailable comparisons are not proof of unchanged content.

**exec.** Runs in its own process group, which is signalled on timeout (default two minutes) or Ctrl-C. Output keeps the start and end of each stream. Effects are reported as none, applied or unknown; a timeout or a cancelled command is unknown. With agents enabled, starting exec while another agent (including the root) has exec running in the same or overlapping canonical workspace roots returns `concurrent_exec` notices identifying the agent, argv and cwd. Notices are bounded and may be marked truncated. Commands are not blocked; each chain step reports its own overlaps.

**Agents.** `--agents` is opt-in. `spawn` starts a Session from a task, brief and optional live paths. `context.entries` selects 1-based parent entries as labelled data; `context.fork` copies history before the current tool batch, fixed at spawn. Sharing follows `/model`'s uncertainty gate for direct tool outcomes; descendant uncertainty remains labelled data to inspect. Same-model forks preserve instructions, declarations and native request prefixes; narrower authority is enforced at dispatch. Other models use model-switch text and report `fork_text`; every history-sharing mode checks byte and estimated context-window limits before admission. Authority defaults to `read`; `write` grants only the parent's available writers and exec. Workspace, authority and plan restrictions stay fixed; only the root has workspace tools and git_do. Agents follow the root's shared working rules plus delegation restrictions. The tree allows depth 3 and 8 live agents; each task has 32 steps, 128 calls and a 200,000 uncached-input plus output token cap.

Parents operate only their own children. Named agents keep history for later `send`; anonymous agents end after delivery. Results arrive once at step boundaries, capped at 32 KiB with a full-trace reference when shortened. Bounded file effects and exec uncertainty survive truncation and reach the root's recap. Every agent waits for its children before finishing; cancellation stops the subtree, and uncertain exec effects require reset. The summary meters root plus descendant tokens; `threads(subtree=true)` lists every descendant and lifetime costs, including released agents, retained across resume (legacy checkpoints are marked incomplete). Omitted wait timeouts wait until done. Chat shows live wait progress, a nested-agent count and finish/delivery notices. There is no background wake. See the tool descriptions and trace-format document for delivery details.

**git_do.** In `recipe` mode the model names the recipe; in `jev` mode a TypeSafe Jev classifier picks it from the model's English intent and declines below a confidence threshold or when the request includes non-git work. Recipes never push the default branch, check their own result, and can be scoped with `paths`. `make git-do-eval` measures selection against real and hand-written cases.

## Context

Instructions are, in order: fixed embedded rules (`instructions.txt`, plus `agent_instructions.txt` for fresh/text-context agents; native forks keep the parent's instructions and append agent guidance with the task), a runtime section of session-fixed facts, the optional friction paragraph, then the workspace root's `AGENTS.md` (up to 32 KiB, off with `--no-project-instructions`). Nothing that changes per request goes in the instructions, so providers can cache the prefix. The rendered text is pinned per session and saved in checkpoints. Anthropic rejects thinking blocks once the system prompt they were made under changes, so a workspace switch or effort change keeps the pin. The `switch_workspace` result carries the new root's `AGENTS.md` instead (or a note to read it when it doesn't fit). The pin is re-rendered only when no earlier provider output is resent: a new session or agent, `/reset`, compaction, or a model transition. Each user message also carries a `workspace_state` snapshot: date, workspace, and Git branch, upstream and change counts. With agents enabled, a sibling `agent_roster` text part holds IDs, names, states and one-line tasks; it is collected afresh after compaction or model switching, not stored in the cached instructions.

`BuildContext` is pure, and `run --show-context` prints the exact first request without a key or network.

**Context GC.** `--context-gc` is off by default and saved across resume. Before in-run compaction, settled passes replace fully superseded or stale file reads and repeated command outputs with stable recall-ID placeholders in the request view only. Stored history, traces, checkpoints, assistant blocks and native reasoning stay intact; file-write digest authorization is unchanged. Failed/uncertain outcomes, agent results and the latest three steps are protected. A pass needs a measured prior request of at least 6.25% of the known model window, at least 15% estimated removable input and 16 steps since the last pass. It must repay a full next-request rebuild minus the encoded instruction/tool values: freed × expected remaining requests × 0.1 > rebuild × (write price − 0.1), with write price 1 for OpenAI and 1.25 for Anthropic. Expected remaining requests equal completed ordinary Session requests, clamped to 16–48; the counter survives resume and compaction. Separately, when `--in-run-compact` can act, a pass may bypass break-even if the conservative next-request estimate is at least 90% of its 40%-window trigger and the post-GC estimate is below that trigger. The floor, removable share and interval still apply. Chat prints one dim notice per pass. Forks inherit the GC view and its recall originals; selected entries and model switches see placeholders. Summaries use that view; after compaction removes an original, recall returns `not_found`. `bench/context_gc.py` replays private traces offline and reports aggregate savings and cache-rebuild costs.

Two mutually exclusive GC experiments require `--context-gc` and are off by default: `REAGENT_CONTEXT_GC_AGE_STEPS=N` (0 disables; otherwise N > 3) evicts unchanged reads after N assistant steps without an explicit tool reference to that canonical file. References mean read/edit/write/delete path arguments or recall of a mapped read ID, including failed calls; prose, search and exec arguments do not count. `REAGENT_CONTEXT_GC_CONSOLIDATE=1` appends one labelled reference entry containing complete, digest-verified reference files assembled from observed ranges, merges overlaps and replaces scattered reads with recall placeholders. Files with incomplete observed coverage stay scattered; it does not load unseen portions or authorize writes. Both use the unchanged full-rebuild, break-even/near-compaction gates, including the net cost of the added entry. Settings survive resume and propagate to agents; neither changes default request bytes. Trace passes record the experiment and reference entry; run headers retain only GC IDs/reasons, not inherited original outcomes. These are experiments, not a recommendation for #141; see the readiness results when available.

**Providers.** OpenAI requests use `store: false` and encrypted reasoning, and carry a `prompt_cache_key`; Anthropic requests use cache breakpoints and merge adjacent user content. `API_PROXY_URL` with `API_PROXY_PROVIDER=openai` sends OpenAI requests through a streaming proxy without a key. Without a proxy, default OpenAI authentication prefers `OPENAI_API_KEY`, then a ChatGPT login with plan permission. `--openai-auth auto|key|chatgpt` overrides `REAGENT_OPENAI_AUTH`; with a proxy, both `auto` and `key` preserve its keyless route, while ChatGPT auth plus `API_PROXY_URL` is an error. Header/status and `run.started` identify the auth mode (`key`, `chatgpt`, `proxy`).

**ChatGPT sign-in.** `reagent login` opens OpenAI's browser approval pages and prints a fallback URL, waits for approval (Ctrl-C cancels), then shows email, plan permission and available models. Approve the re:agent name and “use your ChatGPT plan”; declining saves identity but does not enable inference. The callback page says “Return to re:agent — you can close this tab.” Over SSH, forward the displayed port with `ssh -L <port>:127.0.0.1:<port>`, or paste the browser's final `http://127.0.0.1:<port>/auth/callback?...` URL into the terminal; the first valid arrival uses the same state check. Wrong-state callbacks return 400 and invalid pastes print a diagnostic without ending sign-in. Re-login reuses the saved account; only one account is supported, and logout is not an account switch. `reagent auth status` shows account, permission, expiry and models without tokens. `reagent logout` revokes and clears tokens while retaining installation/account identity; unconfirmed revocation points to ChatGPT settings.

Plan inference uses the streaming encoding, bearer access token and stable UUID `session_id` header; the proxy's existing `session-id` is unchanged. One token source serves all agents, refreshes silently before attempts, reads valid tokens from the atomic file without a file lock, and serializes rotation with a mutex and file lock, re-reading under lock. Started refreshes ignore caller cancellation under a separate 30-second timeout and persist replacements before releasing the lock. Browser approval holds no credential lock; post-callback writes re-read the current registration and reject concurrent registration changes or logout. The optional `logout_generation` counter defaults to zero for old credential files and advances on every logout, including when tokens are already absent, so pending sign-ins cannot undo sign-out. Credentials are atomically stored as 0600 `reagent/chatgpt.json` in the user config directory, never the cache. ID-token claims are validated; signatures are not checked because tokens come directly from the TLS token endpoint. Auth headers, tokens and hint URLs are excluded from traces and previews.

Plus's five-hour usage limit is shared across all plan-using apps; Pro has no such limit. Manage usage at <https://chatgpt.com/settings/usage>. Usage-limit errors stop without retrying and leave the session resumable; wait or restart with `--openai-auth key`. Invalid/expired refresh credentials ask for `reagent login`, never browser approval during a run.

**Endpoints.** `REAGENT_OPENAI_BASE_URL`, `REAGENT_ANTHROPIC_BASE_URL` and `REAGENT_JEV_BASE_URL` select trusted inference destinations, including the API prefix; defaults are `https://api.openai.com/v1`, `https://api.anthropic.com/v1` and `https://api.typesafe.ai/v1`. Append `/responses` (or `/models`), `/messages` and `/systemone` respectively. `REAGENT_OPENAI_AUTH_ISSUER` defaults to `https://auth.openai.com`. Empty values keep defaults; trailing slashes are removed. All four require HTTP(S) and a host, with no query or fragment; invalid values fail at startup without repeating the URL. Endpoint passwords are masked in display/traces. Each destination receives only its provider's credentials; redirects are refused. The keyless streaming `API_PROXY_URL` full endpoint takes precedence for OpenAI only, not Anthropic, Jev or OAuth; ChatGPT auth plus the proxy remains invalid.

**Timeouts.** `REAGENT_RESPONSE_HEADER_TIMEOUT` and `REAGENT_RESPONSE_IDLE_TIMEOUT` override 600-second header and 300-second body-idle defaults for every harness HTTP client, auth included. Values are whole integer seconds in 1–3600; invalid values fail at startup. Existing auth total deadlines still bound those calls.

Completed/incomplete stream events must carry a JSON response object; null or non-object responses stop with `protocol_error`, without dispatch or retry.

**Retries.** By default a request gets two attempts, retrying 429 and 5xx once after 500 ms (except non-retryable ChatGPT admission/usage errors). ChatGPT 401s get one serialized refresh and retry; only the two documented subscription availability stream errors get default bounded retries. Generic stream overloads/rate limits remain non-retried by default. `--model-retry-window 12h` instead retries transport failures, 429/5xx, overload stream errors (matched by code, or by the `service_unavailable_error` type) and streams that end before any terminal event, with backoff until the window closes, including proven pre-send refresh connection failures (TLS negotiation, proxy CONNECT or dial) and explicit temporary auth responses. HTTP connection-acquisition tracing distinguishes these from potentially sent refreshes; untraced injected transports must still prove a dial failure. Ambiguous refresh failures after sending retain tokens but persist `NeedsLogin`, preventing replay even on later turns because rotation may already have consumed the token. Usage from failed attempts is counted; attempts with unknown usage are counted separately. A stream cut off before its terminal event is a `provider_error` that leaves the session resumable, not an `incomplete_response`; an explicit `response.incomplete` still blocks.

## Chat

- An input region at the bottom of the terminal, with status for plan mode, model, auth mode, effort, Auto and context use. Typing during a turn queues the next message; Ctrl-C cancels the turn.
- Commands: `/plan`, `/model`, `/effort`, `/auto`, `/status`, `/context`, `/compact`, `/friction`, `/review`, `/trace`, `/reset`, `/edit`, `/help`, `/exit`. `!command` runs a shell line as the human and records its output.
- **Review.** `/review [low|medium|high|max]` submits an embedded review prompt as an ordinary turn (default medium), targeting the current branch against its default plus uncommitted files. Low is inline; medium/high request parallel read-only finders by angle and a fresh verifier per candidate; max adds a fresh gap sweep and offline executable probes with guarded `zz_review_probe_*` cleanup. All review agents start fresh: the prompt forbids fork/selected-entry history sharing even for cache savings; named sends only retrieve their own bounded pages. The prompt keeps correctness-first candidate/report caps and checks supplied claims against evidence. Medium/high/max have stop budgets of 16/24/40 agents and 0.6/1.2/2 million delegated uncached-input plus output tokens, including paging; cheaper finders leave verification on the review model. Exhausted or unmeasurable budgets leave candidates explicitly unverified and scope uncovered, rather than buying unlimited verification. With agents off, phases run inline without independent verification; read-only/plan mode skips probes. This is model-directed, not runtime-enforced or a hard billing guarantee: root usage is additional and in-flight work can overrun. Bounded historical/current-file comparisons may leave scope uncovered, which the review must disclose.
- **Plan mode** (`--plan`, `/plan`, or `/plan` in a message) refuses writes and `exec`; a reply with a `<plan>` block offers Implement here, Implement fresh, or Keep planning.
- **Context.** `/status` and `/context` show use of the model's window. At 60% chat suggests `/compact`, and at 80% compacts before the next message. `--in-run-compact` also summarizes inside a long run at a conservative 40%-window trigger. Healthy summaries have no count cap: each must shrink the non-reasoning request by at least 15% and leave 16k tokens below that trigger. A failed, invalid or ineffective summary leaves history intact and waits two ordinary model steps before retrying; three consecutive failures disable in-run attempts, and success resets the streak. A summary that cannot pass preflight (window reserve or spare steps) still disables attempts immediately. Provider/cancellation failures still stop resumably. Retry state is per Run, not checkpointed. Summary requests consume the step budget and require room for a follow-up. `REAGENT_CONTEXT_WINDOW_TOKENS` sets a positive testing cap, clamped to a known model's real window; it applies to compaction, GC, admission and display, is labelled in status, traced and saved across resume. Unset preserves normal behavior. See `reagent-port-launch.md` for the pinned-binary #141 recipe.
- **Model switches.** `/model` keeps the conversation and sends earlier history as a labelled text block to the new model; `/model NAME fresh` starts over.
- **Auto** (`--auto`, `/auto on`) asks TypeSafe Jev which model and effort to use at each turn and some mid-run boundaries, among `gpt-6-luna`, `gpt-6-sol` and the configured model.
- **Resume.** Live chat prints a session ID; `--resume ID` restores the checkpointed history. Go reads legacy v1 gob checkpoints and writes deterministic JSON v2 with a SHA-256 payload checksum; opaque native bytes survive exactly. The canonical format is specified in `docs/reagent-rust-parity.md`. Nothing in flight is retried: interrupted tools are reported as unknown effects. Agents end with the process; resumed rosters label them `ended at resume`, never restart them. An agent working at the checkpoint, or with undelivered effects, is also marked `effects_unknown: true`: it may have left changes. This is a conservative observation, not a reconstructed effects ledger.

Replies and auth command results go to stdout; intermediate model text, chat status and diagnostics go to stderr. On a styled terminal, intermediate model text and final replies share Markdown styling and wrapping, without dimming the prose. Harness notices and tool status keep their subdued styling. Redirects and `NO_COLOR` keep literal Markdown without styling or wrapping.

Tool argument type errors name the field and expected JSON type without decoder-specific offsets; syntax errors retain byte positions. Regex errors identify a one-based UTF-8 byte position and owned reason without changing the RE2 dialect. Filesystem, process, transport, terminal and checkpoint failures use owned categories rather than Go/OS prose. Provider/command diagnostics remain bounded external data.

## Traces

One JSONL file per root run (and per compaction or model-switch attempt), and one lifetime trace per agent with its thread and parent IDs, mode 0600, with request and response bodies (credential redaction and UTF-8 replacement where necessary). Invalid UTF-8 runs in embedded native JSON are replaced only in the emitted trace; retained history, continuation requests and checkpoint bytes are unchanged. Parent traces record spawn, send and delivered results, not child histories. Writing is best effort: a failure warns and the run goes on. Event fields and `jq` recipes are in `docs/reagent-trace-format.md`.

## Checking changes

- `make check`: gofmt, vet and the offline tests. `go test ./...` never reaches the internet.
- Go tests use a disposable HOME and XDG cache/config; trace/checkpoint access under the original user cache and credential access under the original user config directory panic with test stacks. Tests with their own homes isolate all three variables. Each tty scenario also has disposable HOME and XDG cache/config.
- `make tty-check`: drives the built binary in a pseudo-terminal through `bench/tty` scenarios; run it for input or display changes.
- `make live`: opt-in live tests for providers whose key is present.
- `bench/` holds offline checkers for friction, behavior comparison and workflow evidence (`docs/reagent-requirement-discovery.md`, `docs/reagent-task-workflow.md`).

## Executable parity

`parity/` is a Python-standard-library black-box runner for a supplied absolute binary path (`make parity BIN=/absolute/reagent`). Each case uses isolated HOME/XDG/cache/config/workspace/artifacts, scripted loopback traffic and fake credentials only. The wire inventory, explicit cross-area dependencies and pinned reference are in `parity/manifest.json`. Git holds normalized digest/length locks, typed ledger contracts, policy, inventory and selected full-case samples—not the complete observation tree. `make parity-golden` archives/builds the exact pinned reference, checks its binary SHA-256, and regenerates replay-validated evidence into an external cache. Candidate runs regenerate missing/stale caches, then compare lossless normalized bytes exactly; they cannot update committed locks. Raw observations and full substitution ledgers stay in the cache for debugging. Cache identity records the resolved temp-root width; candidates with a different or unknown width stop before any case with exit 2 and an explicit regeneration instruction. Case-root allocation is unchanged. Candidate runs delete passing-case artifacts after comparison, retain failures and the report, and print retained bytes; `--keep-artifacts` (`make parity KEEP_ARTIFACTS=1`) retains passing evidence too. See `parity/README.md` for scope, verification evidence and remaining platform work.
