# re:agent — how it works today

This describes the code as it is. It does not decide what re:agent may become: nothing here rules a feature in or out. If this page and the code disagree, the code is right and the page should be fixed. The longer specification it replaces is kept in `docs/archive/` for history only.

## Shape

One Rust crate, `rust/`, building the `reagent` binary. (It began as a Go program; the Rust implementation replaced it after the executable parity campaign below.) It talks to providers over plain HTTP (OpenAI Responses and Anthropic Messages, no SDKs), uses native function tools, and keeps the complete history locally, with each provider's native items preserved so its own conversation continues exactly.

- `reagent run "prompt"` does one task; `reagent chat` holds a conversation.
- `session_api` provides the first trusted-local library boundary: typed open/resume, a cloneable handle, FIFO literal messages, request-ID deduplication, metadata and complete `live_runs` snapshots, exact Run cancellation, retained results, and idle close. One worker owns the Session; reads and cancellation remain available during inference or tools. `reagent run` and interactive chat use it. Chat owns input, parsing and human UI, not the Session; existing provider/tool progress rendering remains a private local owner binding rather than a fully decoupled public stream. The API admits at most 16 live Runs and retains 256 command receipts shared by messages, BTW questions, steers and controls (10 MiB per message/question/steer, 32 MiB total retained inputs), refusing new admission rather than losing retry protection. Cancellation and close remain available at those limits. Explicit close awaits cleanup and releases the checkpoint lease; dropping the last handle requests cancellation and asynchronous cleanup. There is no transport, capability-filtered client, or CLI BTW/steering binding yet. See `docs/reagent-session-api.md` for the remaining design.
- `ask(request_id, question)` admits an isolated, tool-free BTW Run from the latest published settled history/configuration, without waiting for an in-flight model or tool. The full visible prefix is labelled historical data; native reasoning is omitted, arbitrary bytes are explicitly base64-labelled, and unsafe/oversized captures fail without trimming or main compaction. Added serialized capture/configuration storage is capped during native-free construction; an oversized latest source is unavailable, never an older-safe fallback. Staging/encoding runs outside the shared lock, then rechecks source identity, poison and admission limits. Each question owns a fresh ephemeral Session/Provider and cancellation flag, fixes source model/effort without Auto, and reuses the ordinary loop with empty tool specs plus accepted-response/dispatch guards. Loaded scripted responses are shared immutably at an independent captured cursor. Questions and answers never enter main history, agent delivery, file evidence, checkpoint or root/router totals. `RunInfo.kind`, source publication/admission metadata, own trace and usage distinguish them; exact owned references appear in the parent's complete `live_runs` inventory. Main/BTW cancellation and completion are independent; settings/reset/close require both idle, and final handle loss cancels both. Question records/costs last only for this opening, not resume.
- `steer(request_id, target, text)` queues literal trusted user instructions for an exact active conversation Run, not a queued/terminal/BTW Run. It creates no Run and preempts nothing. The Session owner drains FIFO only after the whole accepted tool batch settles, checkpoints attributed user Entries before publishing Applied receipts, and checks the same boundary before text/refusal completion. Admission and completion linearize on one short mutex; a late steer conflicts rather than reaching the next Run. Steers retain current authority, plan, counters, file evidence and trace, share receipt/input limits, and do not count as new turns. `wait_command` waits for application; cancellation targets the Run and settles unapplied guidance independently of BTW. Save failure rolls back only uncommitted steering memory, preserves accepted work/costs, poisons the opening and reports uncertain disk replacement. Resume keeps applied Entry attribution/bytes but reconstructs neither queues nor receipts. Original API messages also carry attribution; optional checkpoint-only byte sidecars preserve new attributed invalid-UTF-8 input while leaving old records' encoding unchanged. No CLI command parsing or display binding was added.
- `change_session` applies typed idle controls for plan mode, reasoning effort, and Auto routing under the same Session owner. Admission checks the expected snapshot revision and excludes messages, other controls, and close until application finishes; `wait_command` waits for the save barrier rather than Run completion. Controls have no Run (`CommandInfo.run` is optional), share message request-ID deduplication and receipt limits, and perform no inference just to change settings. Valid manual effort selection pins Auto, even for the current effort; plan changes do not. Auto metadata includes fallback, allowed routes, accounting, and the existing TypeSafe data-sharing notice. Pinned resume reconstructs dormant catalog routes without requiring old-provider credentials; enable rebases the fallback and revalidates availability. Failed validation preserves settings; checkpoint failure restores memory, blocks the instance, and does not claim disk rollback. Chat translates its local commands into these typed controls; picking the current model or effort still applies the API's default-effort/Auto-pinning behavior.
- `SessionChange::Reset` creates a fresh Session/instance under the same owner, preserving settings, authority and live-opening workspace grants but clearing context, write evidence and root/router counters. The replacement is saved before publication; old handles retain observations and retries but reject new work. `get_replacement()` retrieves the successor without needing a receipt ID; first retrieval hands off ownership, so old inspectors do not keep a claimed successor running. The existing Provider/script cursor continues. Failed reset restores memory, blocks the instance and releases candidate ownership; the original checkpoint remains recoverable, though uncertain I/O may leave a private unpublished candidate checkpoint. Chat Reset and plan-choice Fresh claim this saved replacement and explicitly register its human-consent reader.
- `SessionChange::SwitchModel { model, history }` accepts exact catalog IDs at their default effort and pins Auto, including same-model selections. `HistoryMode::Carry` preserves identity, source history, cumulative usage and file evidence while validating a native-free visible handoff from the GC view for the destination. Successful Carry atomically invalidates published `last_request` calibration to unknown zero after saving, even for same-model selection; ordinary inference still retains the latest reported usage, and failed switches preserve it. `Fresh` uses reset's saved replacement/ownership path with the new model, empty context and counters, and preserved authority/grants. Both stage locally without inference; validation leaves bindings untouched, and save failure restores the Provider and memory, poisons the old opening, and makes no disk-rollback claim. Scripted Sessions reject model switching. Chat resolves positions/aliases locally to exact catalog IDs and uses these same Carry/Fresh controls.
- `Compact { focus }` and trusted-human `RunUserShell { command }` are cancellable long controls without Runs. `wait_command` includes execution and terminal saves; `cancel_command` targets exact command receipts independently of capacity or current lifecycle. Compaction uses one non-routed summary request, counts reported/possible unreported costs once, publishes settled calibration even on failure, preserves plan transitions across intervening shell observations, and clears history/write evidence only after a successful final save. Human shell shares its bounded raw-byte capture and scrubbed process runner with the CLI, bypasses model read-only/plan restrictions without changing them, and records output for the next message without inference. A pre-spawn checkpoint preserves possible unknown shell effects; interruption never replays work or silently allows an unsafe handoff. Post-action save failure retains costs/observations, poisons memory, and makes no disk-rollback claim. Public API control cancellation flags stay locally owned. CLI admission binds its actual signal flag before owner publication and anchors only actual SIGINT consumers; rejected admissions install nothing. Raw capture survives display-only UTF-8 repair. Tree cleanup never targets a reaped PID; outliving background work is left running with explicit unknown effects. Cleanup is cooperative, not containment or a hard shutdown bound. These remain trusted-local controls, not model tools or a remote capability boundary.
- Structured `get_context`, `read_entries`, `read_agents` and `read_events` observations read owned published caches without tools, HTTP or a Session guard, including while the owner is busy and after close/replacement or persistence failure. Typed content retains bounded exact bytes and explicit omissions, never reasoning/native provider items or raw configuration; pages fit 256 KiB, with generation-bound cursors and no oversized-Entry skips. Source history rewrites expire Entry cursors, unchanged Carry does not, and retired handles keep their own cache. Numeric context marks incomplete batches, uncertain effects and unavailable local measurements explicitly; scripted generation never claims a provider wire size. Recovered shell observations preserve conservative capture incompleteness and withhold pre-spawn warning prose as unavailable process capture. The lifetime agent roster is observed at owner boundaries, not freshly polled by reads. A bounded 256-event log shares the snapshot's atomic revision/cursor, reports eviction gaps and every discarded queued Run's terminal transition, and supports condition-variable waits with caller-local cancellation; it is not durable replay or an event bus. Trusted-local content may be sensitive; there is still no remote authorization boundary.
- `register_workspace_consent(timeout_ms)` binds one cloneable trusted-local human guard to an API opening, including during an active Run. Its typed pending request contains exact validated destination bytes and current plan/read-only flags; snapshots/events expose only approval/Run/deadline references. Only the guard can read/answer that pending human request. The API-owned adapter waits on the existing condition variable with a 1–300000 ms deadline and exact Run cancellation; absent owners fail promptly with `permission_required`, and final guard/client loss cannot leave a permanent human wait. Resolutions share the bounded command ledger: `Applied` registers a live human decision, not a grant or durable save. Shared workspace tools revalidate point-in-time directory existence/identity through consent and final publication, reject changed cached roots without losing file evidence, and check newly opened roots against the validated proof before publishing metadata/instructions. Changes from missing to existing while pending require a fresh request; creation after a successful prospective reservation still works. These guards also benefit legacy consumers, preserve bootstrap/path-scoped grants, and are not an OS sandbox or continuous filesystem-identity pin. Allow never creates/selects a missing destination or lifts restrictions; absent-adapter guidance includes Rust registration plus interactive chat/`--allow-workspace PATH` remedies. Reset/Fresh preserve live grants but require new human registration; resume reconstructs neither pending consent nor extra live grants. The guard weakly references the opening and cannot keep a worker or replacement alive. Interactive chat uses this guard and its sole input reader for the typed picker; withdrawal is checked without waiting for keyboard input. Reader errors withdraw the role and cancel the exact operation; EOF withdraws the role without treating otherwise ongoing work as an error. Piped chat registers no human and fails promptly unless the path is preapproved. No listener/remote authorization layer was added.
- A **Session** holds what outlives a run: configuration, the accepted transcript, every call ID, workspace grants. A **Run** is one user turn's loop: request, accept the response, dispatch its tool calls in order, repeat until a tool-free reply passes the completion gate without pending guidance or agent delivery.
- Runs end with a distinct status: completed, refused, cancelled, provider error, incomplete response, protocol error, limit exceeded, effect unknown, tool internal error, persistence error. `completed` means the model replied, not that the task succeeded.
- After completed or refused, the session continues. A provider error before a response was accepted is marked `resumable`. Cancellation also leaves a settled tool batch continuable: the next message includes an interruption notice and unknown-effects warning; accepted calls are never replayed. An exec timeout goes back to the model to inspect. Other outcomes block the chat until `/reset` or `/compact`; uncertainty still prevents model/context handoffs.
- Budgets (`--max-steps`, `--max-tool-calls`) are off by default. An accepted tool call is never run twice and never retried automatically.
- re:agent fails fast on any thread panic: its startup hook restores raw terminal input, prints the panic to stderr, and aborts the process (release builds also use `panic = "abort"`). Resume uses the last checkpoint without restarting pending work. Root reset releases retired agent trees once their remaining workers stop.

## Tools

| Tool | What it does |
|---|---|
| `list_files`, `read_file`, `search_text` | Read the active workspace; results fit a 32 KiB budget and say when they are incomplete |
| `edit_file`, `write_file`, `delete_file` | Guarded text edits, creation and deletion; opt-in recursive deletion |
| `git_inspect` | Read status, staged/committed diffs, raw worktree diffs, historical files and logs in every mode, without configured programs or network; partial clones are refused |
| `exec` | Run an argv (no shell) with a timeout, optionally chained with `then` |
| `recall` | With `--context-gc`, retrieve a dropped tool outcome by its original call ID, in every mode and for agents |
| `request_workspace_access`, `switch_workspace` | Ask the human for another root, and move to it |
| `spawn`, `send`, `wait`, `threads`, `cancel`, `dismiss`, `reset` | Concurrent agents (default on) with per-spawn read/write authority, operated only by their parent |
| `report_friction` | With `--report-friction`: root and children report harness friction, sharing the 10-report process cap; traces attribute each report |
| `git_do` | Default on in `recipe` mode: run one of twelve fixed git recipes and return proof; `--git-do jev` selects a classifier, `--git-do off` disables it |

Paths stay inside the active root and skip `.git`, `.env` and `.env.*`; these are ordinary checks, not a sandbox, and `exec` is not bound by them. Rust workspace selection rejects non-UTF-8 canonical destinations rather than converting them lossily; Go preserves native path bytes. `--read-only` withholds the writers and `exec`; plan mode refuses them at dispatch.

**Files.** Reads are capped at 1 MiB and requests at 10 MiB. Writers check an optional `expected_sha256`, or the last digest that conversation saw. With agents enabled, file-tool checks and publication share a tree-wide guard; observations remain local, and deleted observed files require an absence read before recreation. Exec and external editors do not participate. `edit_file` supports exact replacements, `edits`, `replace_all` and `append_text`; near misses report candidate lines rather than fuzzy-applying. Explicit digests let `delete_file` stream-hash large binaries; `recursive:true` deletes trees without following symlinks and reports actual removals, including partial failure.

File-tool changes have numbered, interleaved previews with two context lines and a shared twelve-row budget. Recursive deletions label each shown child's path and count additional files; carriage returns stay visibly escaped, including CRLF-only changes. Turn summaries include child file-tool publications and report net files and added/removed lines; `/diff` shows the last turn's captured hunks without the preview row cap. Presentation reuses the bounded git diff routine and keeps publication snapshots outside model outcomes, requests, traces and checkpoints. Only the latest completed turn retains its CLI display snapshots; earlier command receipts and results remain available without those file contents. Binary, oversized, discontinuous or over-budget changes are marked unavailable/partial rather than silently omitted; exec and external-editor changes are not captured.

**git_inspect.** `status` separates staged changes (base → index), unstaged changes (index → raw worktree) and untracked paths. `worktree_diff` compares raw files, including untracked additions, to `rev` (default `HEAD`); both accept literal `paths`, and `worktree_diff` accepts `stat:true`. `diff` with `staged:true` compares `from` (default `HEAD`) to the index, without `to`. Go hashes raw files using the repository's object format, never follows symlink content or descends into gitlinks, and reports special index flags as unknown comparisons. Conversion attributes/config are marked “comparison not filter-aware.” Attribute lookup uses one NUL-delimited stdin request, not per-file batches. Bounded deterministic Myers diffs use three context lines; pure additions/deletions render directly without the search-distance cap. Binary, oversized or over-budget inputs show sizes/blob IDs instead. Narrow truncated results with `paths`; unavailable comparisons are not proof of unchanged content.

**exec.** Runs in its own process group. On timeout (default two minutes) or Ctrl-C, a PPID snapshot (`ps` on Darwin, `/proc` on Linux) identifies descendants, including detached sessions. Their groups receive TERM, then KILL after a grace period; surviving PIDs or unverifiable cleanup are reported with unknown effects. Linux discovery ignores vanished PIDs (`ENOENT` or `ESRCH`); other read errors still make cleanup unverifiable. A double-forked process reparented before the snapshot can still escape: this is cleanup, not process containment. Output keeps the start and end of each stream. Effects are reported as none, applied or unknown; a timeout or a cancelled command is unknown. With agents enabled, starting exec while another agent (including the root) has exec running in the same or overlapping canonical workspace roots returns `concurrent_exec` notices identifying the agent, argv and cwd. Notices are bounded and may be marked truncated. Commands are not blocked; each chain step reports its own overlaps.

**Agents.** Agents are enabled by default for `run` and `chat`; `--agents=false` disables them. Scripted replay keeps them disabled and rejects explicit `--agents`. Resumed chats retain their saved setting. `spawn` starts a Session from a task, brief and optional live paths. `context.entries` selects 1-based parent entries as labelled data; `context.fork` copies history before the current tool batch, fixed at spawn. Sharing follows `/model`'s uncertainty gate for direct tool outcomes; descendant uncertainty remains labelled data to inspect. Same-model forks preserve instructions, declarations and native request prefixes; narrower authority is enforced at dispatch. Other models use model-switch text and report `fork_text`; every history-sharing mode checks byte and estimated context-window limits before admission. Authority defaults to `read`; `write` grants only the parent's available writers and exec. Workspace, authority and plan restrictions stay fixed; only the root has workspace tools and git_do. Agents follow the root's shared working rules plus delegation restrictions. Because a fork resends the parent's context on every child request, the `spawn` description steers narrow file- or module-scoped tasks, and parents above about 100k tokens, to a fresh complete brief, and asks for shared prerequisites up front with amendments batched into one `send`. The tree allows depth 3 and 16 live agents, including idle teammates. `spawn.kind` defaults to `task`: each task has 64 steps, 256 calls and a 400,000 uncached-input plus output token cap. `kind:"teammate"` requires a name and root admission; teammates have no fixed step, call or task-token cap. Kind does not change authority, context-window limits or cancellation. A step cap or an excess tool-call batch reserves one final summary request (at most 8,192 output tokens, including reasoning, and two minutes, no retries), counted in usage and steps and marked `agent.cap_summary` in the trace. Summary requests retain tool declarations for native history and caching, but reject response tool calls. Exactly 256 calls still permits a normal text-only completion. Delivery keeps `limit_exceeded` and applied effects; a failed summary falls back to the last assistant text.

Parents operate only their own children. Tasks end after their final result is delivered, even when named. Teammates keep history for later `send` until explicitly dismissed or the Session shuts down; idle teammates retain state but no worker thread. Kind is fixed at spawn and included in roster and lifetime observations. Old checkpoints without kind are interpreted as tasks; resumption still restores ended observations, not running workers. Results arrive once at step boundaries, capped at 32 KiB with a full-trace reference when shortened. Bounded file effects and exec uncertainty survive truncation and reach the root's recap. Every agent waits for its children before finishing; cancellation stops the subtree, and uncertain exec effects require reset. The summary meters root plus descendant tokens; `threads(subtree=true)` lists every descendant and lifetime costs, including released agents, retained across resume (legacy checkpoints are marked incomplete). Omitted wait timeouts wait until done. Chat shows live wait progress and one transient activity/elapsed row per working descendant, capped at a third of the terminal height. Rows refresh during parent tools as well as inference and wait; long names yield space to activity and elapsed time. Resizing reanchors the pane and clears the visible page, preserving existing scrollback. Finished rows disappear without scrollback; one completion notice includes the reply's first line. Successful wait/dismiss/threads/reset calls join the end-of-turn count; failures and timeouts remain visible. Recaps group known file effects by agent, while uncertain effects remain explicit (delivery stays in the trace). There is no background wake. See the tool descriptions and trace-format document for delivery details.

**git_do.** `run` and `chat` default to `recipe` mode: the model names the recipe and no router key is needed. `--git-do off` disables the tool; the legacy empty value also disables it. The mode is not saved across resume, which uses the default. Read-only mode withholds it, plan mode refuses execution, and children cannot use it. In `jev` mode a TypeSafe Jev classifier picks it from the model's English intent and declines below a confidence threshold or when the request includes non-git work. Recipes never push the default branch, check their own result, and can be scoped with `paths`. Already-committed scoped paths skip the commit and let publishing continue; plain `commit` reports that nothing was staged. PR follow-ups use an explicit preflight-tip lease for rewritten history only when the observed tip appears in the current branch's own reflog. They decline before staging or committing if the remote moved or the rewrite cannot be established. `rebase_push` reads the remote tip before fetching and declines unless it is an ancestor of HEAD, then pushes with an explicit lease for that tip; a never-pushed branch leases the remote branch's absence. `make git-do-eval` measures selection against real and hand-written cases.

## Context

Instructions are, in order: fixed embedded rules (`instructions.txt`, plus `agent_instructions.txt` for fresh/text-context agents; native forks keep the parent's instructions and append agent guidance with the task), a runtime section of session-fixed facts, the optional friction paragraph, then the workspace root's `AGENTS.md` (up to 32 KiB, off with `--no-project-instructions`). Nothing that changes per request goes in the instructions, so providers can cache the prefix. The rendered text is pinned per session and saved in checkpoints. Anthropic rejects thinking blocks once the system prompt they were made under changes, so a workspace switch or effort change keeps the pin. The `switch_workspace` result carries the new root's `AGENTS.md` instead (or a note to read it when it doesn't fit). The pin is re-rendered only when no earlier provider output is resent: a new session or agent, `/reset`, compaction, or a model transition. Each user message also carries a `workspace_state` snapshot: date, workspace, and Git branch, upstream and change counts. With agents enabled, a sibling `agent_roster` text part holds IDs, names, states and one-line tasks; it is collected afresh after compaction or model switching, not stored in the cached instructions.

`BuildContext` is pure, and `run --show-context` prints the exact first request without a key or network.

**Context GC.** Context GC is on by default for new run/chat sessions; `--context-gc=false` disables it. Resume preserves the saved setting, including off in older sessions. Before in-run compaction, settled passes replace fully superseded or stale file reads and repeated command outputs with stable recall-ID placeholders in the request view only. Stored history, traces, checkpoints, assistant blocks and native reasoning stay intact; file-write digest authorization is unchanged. Opus 5.5 requests containing GC placeholders opt into `thinking-binding-controls-2026-08-01` with `thinking.block_binding.prefix_mismatch_behavior: drop_block`, letting the server discard thinking whose signed conversation prefix GC invalidated without rewriting the retained blocks. Other models keep their existing request format: Haiku and Sonnet 5.5 reject that option without an explicit thinking mode, which GC must not enable. Failed/uncertain outcomes, agent results and the latest three steps are protected. A pass needs a measured prior request of at least 6.25% of the known model window, at least 15% estimated removable input and 16 steps since the last pass. It must repay a full next-request rebuild minus the encoded instruction/tool values: freed × expected remaining requests × 0.1 > rebuild × (write price − 0.1), with write price 1 for OpenAI and 1.25 for Anthropic. Expected remaining requests equal completed ordinary Session requests, clamped to 16–48; the counter survives resume and compaction. Separately, when `--in-run-compact` can act, a pass may bypass break-even if the conservative next-request estimate is at least 90% of its 40%-window trigger and the post-GC estimate is below that trigger. The floor, removable share and interval still apply. Chat prints one dim notice per pass. Forks inherit the GC view and its recall originals; selected entries and model switches see placeholders. Summaries use that view; after compaction removes an original, recall returns `not_found`. `bench/context_gc.py` replays private traces offline and reports aggregate savings and cache-rebuild costs.

Two mutually exclusive GC experiments require GC to remain enabled and are off by default: `REAGENT_CONTEXT_GC_AGE_STEPS=N` (0 disables; otherwise N > 3) evicts unchanged reads after N assistant steps without an explicit tool reference to that canonical file. References mean read/edit/write/delete path arguments or recall of a mapped read ID, including failed calls; prose, search and exec arguments do not count. `REAGENT_CONTEXT_GC_CONSOLIDATE=1` appends one labelled reference entry containing complete, digest-verified reference files assembled from observed ranges, merges overlaps and replaces scattered reads with recall placeholders. Files with incomplete observed coverage stay scattered; it does not load unseen portions or authorize writes. Both use the unchanged full-rebuild, break-even/near-compaction gates, including the net cost of the added entry. Settings survive resume and propagate to agents; neither changes default request bytes. Trace passes record the experiment and reference entry; run headers retain only GC IDs/reasons, not inherited original outcomes. These are experiments, not a recommendation for #141; see the readiness results when available.

**Providers.** `gpt-6.1-terra` is selectable as model 2 or by name. Anthropic defaults to `claude-haiku-5-5` (model 4), replacing `claude-haiku-4-5` in the catalog. Terra has a 1,050,000-token window and Haiku a 1,000,000-token window, enabling window-based GC, compaction, Auto and history handoffs without an override. Both retain provider-default effort/verbosity because effort support remains unverified. Normal run/chat defaults to `gpt-6.1-sol` at high effort; explicit model/environment and effort selections override it. Selecting 6.1 Sol also defaults to high; 6.1 Luna defaults to medium with a 1,050,000-token window and supports none through max. Auto defaults separately to 6.1 Sol/medium. The GPT-6 and GPT-5.6 models are no longer in the catalog; the CLI still accepts explicit custom names, including removed IDs. OpenAI requests use `store: false` and encrypted reasoning, and carry a `prompt_cache_key`; Anthropic requests use cache breakpoints and merge adjacent user content. `API_PROXY_URL` with `API_PROXY_PROVIDER=openai` sends OpenAI requests through a streaming proxy without a key. Without a proxy, default OpenAI authentication prefers `OPENAI_API_KEY`, then a ChatGPT login with plan permission. `--openai-auth auto|key|chatgpt` overrides `REAGENT_OPENAI_AUTH`; with a proxy, both `auto` and `key` preserve its keyless route, while ChatGPT auth plus `API_PROXY_URL` is an error. Header/status and `run.started` identify the auth mode (`key`, `chatgpt`, `proxy`).

**ChatGPT sign-in.** `reagent login` opens OpenAI's browser approval pages and prints a fallback URL, waits for approval (Ctrl-C cancels), then shows email, plan permission and available models. Approve the re:agent name and “use your ChatGPT plan”; declining saves identity but does not enable inference. The callback page says “Return to re:agent — you can close this tab.” Over SSH, forward the displayed port with `ssh -L <port>:127.0.0.1:<port>`, or paste the browser's final `http://127.0.0.1:<port>/auth/callback?...` URL into the terminal; the first valid arrival uses the same state check. Wrong-state callbacks return 400 and invalid pastes print a diagnostic without ending sign-in. Re-login reuses the saved account; only one account is supported, and logout is not an account switch. `reagent auth status` shows account, permission, expiry and models without tokens. `reagent logout` revokes and clears tokens while retaining installation/account identity; unconfirmed revocation points to ChatGPT settings.

Plan inference uses the streaming encoding, bearer access token and stable UUID `session_id` header; the proxy's existing `session-id` is unchanged. One token source serves all agents, refreshes silently before attempts, reads valid tokens from the atomic file without a file lock, and serializes rotation with a mutex and file lock, re-reading under lock. Started refreshes ignore caller cancellation under a separate 30-second timeout and persist replacements before releasing the lock. Browser approval holds no credential lock; post-callback writes re-read the current registration and reject concurrent registration changes or logout. The optional `logout_generation` counter defaults to zero for old credential files and advances on every logout, including when tokens are already absent, so pending sign-ins cannot undo sign-out. Credentials are atomically stored as 0600 `reagent/chatgpt.json` in the user config directory, never the cache. ID-token claims are validated; signatures are not checked because tokens come directly from the TLS token endpoint. Auth headers, tokens and hint URLs are excluded from traces and previews.

Plus's five-hour usage limit is shared across all plan-using apps; Pro has no such limit. Manage usage at <https://chatgpt.com/settings/usage>. Usage-limit errors stop without retrying and leave the session resumable; wait or restart with `--openai-auth key`. Invalid/expired refresh credentials ask for `reagent login`, never browser approval during a run.

**Endpoints.** `REAGENT_OPENAI_BASE_URL`, `REAGENT_ANTHROPIC_BASE_URL` and `REAGENT_JEV_BASE_URL` select trusted inference destinations, including the API prefix; defaults are `https://api.openai.com/v1`, `https://api.anthropic.com/v1` and `https://api.typesafe.ai/v1`. Append `/responses` (or `/models`), `/messages` and `/systemone` respectively. `REAGENT_OPENAI_AUTH_ISSUER` defaults to `https://auth.openai.com`. Empty values keep defaults; trailing slashes are removed. All four require HTTP(S) and a host, with no query or fragment; invalid values fail at startup without repeating the URL. Endpoint passwords are masked in display/traces. Each destination receives only its provider's credentials; redirects are refused. The keyless streaming `API_PROXY_URL` full endpoint takes precedence for OpenAI only, not Anthropic, Jev or OAuth; ChatGPT auth plus the proxy remains invalid.

**Timeouts.** `REAGENT_RESPONSE_HEADER_TIMEOUT` and `REAGENT_RESPONSE_IDLE_TIMEOUT` override 600-second header and 300-second body-idle defaults for every harness HTTP client, auth included. Values are whole integer seconds in 1–3600; invalid values fail at startup. Existing auth total deadlines still bound those calls. `REAGENT_WORKSPACE_GIT_TIMEOUT` (whole seconds, 1–3600, default 2) bounds each workspace-snapshot Git probe; a probe that times out leaves the snapshot's Git section out.

Completed/incomplete stream events must carry a JSON response object; null or non-object responses stop with `protocol_error`, without dispatch or retry. Streams that reconstruct credentials across decoded deltas, including interleaved blocks, are discarded before acceptance; their response body is withheld from traces rather than recording recoverable fragments.

**Retries.** By default a request gets two attempts, retrying 429 and 5xx once after 500 ms (except non-retryable ChatGPT admission/usage errors). ChatGPT 401s get one serialized refresh and retry; only the two documented subscription availability stream errors get default bounded retries. Generic stream overloads/rate limits remain non-retried by default. `--model-retry-window 12h` instead retries transport failures, 429/5xx, overload stream errors (OpenAI overload codes/`service_unavailable_error`, and Anthropic overload/rate-limit/API errors) and streams from either provider that end before any terminal event, with backoff until the window closes, including proven pre-send refresh connection failures (TLS negotiation, proxy CONNECT or dial) and explicit temporary auth responses. HTTP connection-acquisition tracing distinguishes these from potentially sent refreshes; untraced injected transports must still prove a dial failure. Ambiguous refresh failures after sending retain tokens but persist `NeedsLogin`, preventing replay even on later turns because rotation may already have consumed the token. Usage from failed attempts is counted once, including input/cache/output counts already reported by failed Anthropic streams; partial totals stay explicitly unknown. Attempts with unknown usage are counted separately. A stream cut off before its terminal event is a `provider_error` that leaves the session resumable, not an `incomplete_response`; an explicit `response.incomplete` still blocks. Anthropic `max_tokens` also yields `incomplete_response` with reported usage, even when streamed tool arguments end as incomplete JSON; no partial tool call is accepted.

## Chat

- Bare `reagent` (or `reagent [chat flags]`) starts chat when stdin, stdout and stderr are terminals; bare piped invocations still print usage. Explicit `run`, `chat` and scripted replay keep their behavior.
- The welcome shows the colored flask beside session details on terminals at least 72 columns wide; narrow terminals and plain output use a compact text fallback. Both shorten the workspace path and include the resume hint when checkpoints are enabled. Submitted messages stay in scrollback without rules, on a subtle neutral background; only the live input keeps its frame. A shared 256-colour palette gives headings and file writes the flask's teal accent, read-only tool names muted grey, commands purple, and success/warning/error marks green/gold/red. `NO_COLOR` and redirected output retain plain text. Completed turns end with one dim elapsed/tool/token summary, adding tree usage only when agents ran. `/status` retains detailed usage; non-completed turns and `run` keep their detailed summaries, and `--recap` still prints effects.
- An input region at the bottom of the terminal, with status for plan mode, model, auth mode, effort, enabled Fast mode, Auto and context use, refreshed after accepted responses and in-run compaction. The last known usage stays visible while a request is in flight. Typing during a turn queues the next message; Up or Backspace restores it as a draft, and Enter queues the edited message again. Ctrl-C or Esc cancels the turn and clears queued typeahead. Interrupted exec effects remain visibly unknown, but the normal prompt accepts a follow-up without reset. Read, listing and search calls show transient progress without adding transcript rows. A teal animated flask above the input frame shows separate alchemy-themed thinking and writing phrases rotating every four seconds, elapsed time and estimated output-token counts; model and step stay in the status row. `NO_COLOR` keeps the animation without styling. Running exec shows the current chained command and a dim, width-truncated five-line output tail, then collapses to its single result row; captured tool results are unchanged. Exec publishes its preview without waiting for the terminal, so a stalled display does not delay process timeout or cancellation. Both providers stream reply lines above the indicator (reported Anthropic usage updates progress). Speculative previews retain at most 128 completed lines and 16 KiB, preserving code-fence state; lines over 8 KiB are omitted and oversized SSE events disable further text preview. Cached layout keeps draft/spinner redraw work bounded. Full accepted replies, history and trace bodies are not clipped. Partial previews never enter accepted history and disappear on failure or retry. Redirected output still prints only accepted replies.
- **Editing.** Ctrl-Left/Right (also Alt-B/F) move by word; Alt-Backspace/Ctrl-W erase backward, Alt-D erases the next word, and Ctrl-D deletes forward unless the buffer is empty, when it exits. Alt-Enter and Ctrl-J insert editable newlines; Up/Down move between displayed rows before browsing history. Matching slash commands appear below the input with descriptions; Up/Down select, Tab accepts, and Esc dismisses suggestions while idle. Interactive input history is shared across chats in the same canonical workspace, stored privately (0600) under the platform cache's `reagent/input-history/` directory. It retains at most 500 entries and 8 MiB, skips individually oversized inputs, and records queued messages only when dispatched. A cache error falls back to in-memory history with a warning. Ctrl-R search is not implemented.
- Commands: `/plan`, `/model`, `/effort`, `/fast`, `/auto`, `/status`, `/context`, `/compact`, `/friction`, `/review`, `/trace`, `/diff`, `/reset`, `/edit`, `/help`, `/exit`. Settings, model switches, compaction, human shell and Reset use typed SessionApi controls; status/context/trace are read-only observations and do not rewrite checkpoints. Receipt/input exhaustion is reported with explicit stop/resume guidance, never hidden by eviction or a fresh opening. Scripted chat retains its model/effort/Auto/manual-compaction restrictions.
- **Review.** `/review [low|medium|high|max]` submits an embedded review prompt as an ordinary turn (default medium), targeting the current branch against its default plus uncommitted files. Low is inline; medium/high request parallel read-only finders by angle and a fresh verifier per candidate; max adds a fresh gap sweep and offline executable probes with guarded `zz_review_probe_*` cleanup. All review agents start fresh: the prompt forbids fork/selected-entry history sharing even for cache savings; named sends only retrieve their own bounded pages. The prompt keeps correctness-first candidate/report caps and checks supplied claims against evidence. Medium/high/max have stop budgets of 16/24/40 agents and 0.6/1.2/2 million delegated uncached-input plus output tokens, including paging; cheaper finders leave verification on the review model. Exhausted or unmeasurable budgets leave candidates explicitly unverified and scope uncovered, rather than buying unlimited verification. With agents off, phases run inline without independent verification; read-only/plan mode skips probes. This is model-directed, not runtime-enforced or a hard billing guarantee: root usage is additional and in-flight work can overrun. Bounded historical/current-file comparisons may leave scope uncovered, which the review must disclose.
- **Plan mode** (`--plan`, `/plan`, or `/plan TEXT`) refuses writes and `exec`; a reply with a `<plan>` block offers Implement here, Implement fresh, or Keep planning. The chooser applies explicit controls and a literal implementation message; turning planning off never lifts launch read-only authority.
- **Context.** `/status` and `/context` show use of the model's window. At 80% known usage the exclusive Session owner compacts before the next message, for CLI and library callers alike. It skips scripted/unknown-window/unknown-usage/blocked/empty/off cases; a failed non-cancelled summary saves suppression together with accounting in one settlement checkpoint and suppresses automatic attempts until successful manual compaction, Reset or model change. Summary costs are counted once, without an extra Run or Auto call. Cancellation leaves the intended message unapplied and never replays it; checkpoint failure poisons the opening before further inference. In-run compaction is on by default for new CLI `run` and `chat` sessions; `--in-run-compact=false` disables it, and resume preserves the saved setting (including off in older sessions). Child agents still disable it. It summarizes inside a long run at a conservative 40%-window trigger. In-run summaries must fit the 32 KiB handoff limit; prompts ask for 24 KiB because models overshoot a stated budget. An oversized reply gets up to two shortening requests within the same attempt (24 KiB, then 12 KiB targets), each traced as `compaction.shorten` and subject to the window reserve and spare steps, before counting one failure (#189). Healthy summaries have no count cap: each must shrink the non-reasoning request by at least 15% and leave 16k tokens below that trigger. A failed, invalid or ineffective summary leaves history intact and waits two ordinary model steps before retrying; three consecutive failures disable in-run attempts, and success resets the streak. A summary that cannot pass preflight (window reserve or spare steps) still disables attempts immediately. Provider/cancellation failures still stop resumably. Retry state is per Run, not checkpointed. Summary requests consume the step budget and require room for a follow-up. `REAGENT_CONTEXT_WINDOW_TOKENS` sets a positive testing cap, clamped to a known model's real window; it applies to compaction, GC, admission and display, is labelled in status, traced and saved across resume. Unset preserves normal behavior. See `reagent-port-launch.md` for the pinned-binary #141 recipe.
- **Model switches.** `/model` keeps the conversation and sends earlier history as a labelled text block to the new model; `/model NAME fresh` starts over with a saved replacement. Selecting even the current model uses its catalog default effort and pins Auto; valid current-effort selection also pins Auto. Picker cancellation changes nothing.
- **Fast mode.** `/fast` toggles faster service; `/fast on|off` sets it explicitly. It defaults off, keeps the same model and reasoning effort, and costs higher token rates. `/status` reports on/off and the input status shows a marker only while enabled. Verified catalog models are OpenAI `gpt-6.1-terra`, `gpt-6.1-sol` and Anthropic `claude-opus-5-5` (Opus 5.5); enabling it on unsupported or unverified models (including `gpt-6.1-luna`) is rejected without changing settings. The setting survives checkpoint/resume and Reset. Compatible model changes and child agents retain it; unsupported model changes, Auto routes and children disable it. BTW questions capture the setting with their source configuration.
- **Auto** (`--auto`, `/auto on`) asks TypeSafe Jev which model and effort to use at each turn and some mid-run boundaries, among `gpt-6.1-luna`, `gpt-6.1-sol` and the configured model. Enabled CLI startup/resume (including one-shot `run --auto`) and explicit enable disclose the existing full data-sharing warning before inference; disabled/pinned startup does not. Packets may contain conversation/tool/shell secrets and are not secret-filtered.
- **Human shell.** `!command` sends exact command bytes to the trusted-human control. Live display consumes bounded offset-addressed shell events, joins split UTF-8, sanitizes controls and visibly wraps newline-free fragments at 4096 raw bytes so the region cannot accumulate an invisible unbounded shell line; retained final raw capture and the legacy history projection remain separate from display. An event gap is explicit and prints the final bounded capture with a repetition warning. A never-started shell says no Entry was added; failed terminal saving says the observation is retained only in memory. Cancelled/unknown-effect shell work blocks subsequent messages until explicit recovery, unlike the old CLI continuation. Successful outliving background work is not killed after reap; cleanup is not containment.
- **Resume.** `reagent --continue` resumes the most recently saved Session launched in the current canonical workspace (`--workspace DIR` selects another). `reagent --resume` opens a paged terminal picker with checkpoint modification time, workspace and first-message preview; cancelling exits without opening a Session. `reagent [chat] --resume ID` still works without a terminal. Missing sessions fail rather than starting fresh. Discovery validates private checkpoints without locking or rewriting them; corrupt entries are omitted. A bounded optional `first_message` preview survives compaction; older checkpoints fall back to the first retained user message, or an empty label if none remains. Live chat still prints the session ID; resumption restores the checkpointed history. It reads legacy v1 gob checkpoints written by the Go implementation and writes deterministic JSON v2 with a SHA-256 payload checksum; opaque native bytes survive exactly. The canonical format is specified in `docs/reagent-rust-parity.md`. Nothing in flight is retried: interrupted tools are reported as unknown effects. Agents end with the process; resumed rosters label them `ended at resume`, never restart them. An agent working at the checkpoint, or with undelivered effects, is also marked `effects_unknown: true`: it may have left changes. This is a conservative observation, not a reconstructed effects ledger.

Replies and auth command results go to stdout; intermediate model text, chat status and diagnostics go to stderr. On a styled terminal, intermediate model text and final replies share Markdown styling and wrapping, without dimming the prose. Code blocks hide their fences behind a dim left bar and optional language label, with green additions and red removals in `diff` blocks. Links use underlined OSC 8 terminal hyperlinks; wrapped rows close and reopen links so surrounding text stays unlinked. Harness notices and tool status keep their subdued styling. Redirects and `NO_COLOR` keep literal Markdown without styling or wrapping.

Tool argument type errors name the field and expected JSON type without decoder-specific offsets; syntax errors retain byte positions. Regex errors identify a one-based UTF-8 byte position and owned reason without changing the RE2 dialect. Filesystem, process, transport, terminal and checkpoint failures use owned categories rather than Go/OS prose. Provider/command diagnostics remain bounded external data.

## Traces

One JSONL file per root Run, compaction attempt and configured catalog model-switch attempt, and one lifetime trace per agent with its thread and parent IDs, mode 0600, with request and response bodies (credential redaction and UTF-8 replacement where necessary). Invalid UTF-8 runs in embedded native JSON are replaced only in the emitted trace; retained history, continuation requests and checkpoint bytes are unchanged. Parent traces record spawn, send and delivered results, not child histories. Owner operation IDs are not conversation Runs and use trace Step 0; summary traces include actual HTTP attempts and cost, while model-switch traces retain measured size, latency and handoff digest rather than handoff content. `/trace` follows the latest attempted operation, including diagnostic staging refusals that do not change settings/history. Writing is best effort: a failure warns and work goes on; files may be partial after I/O failure or crash. Event fields and `jq` recipes are in `docs/reagent-trace-format.md`.

`bench/friction.py` derives root and child-agent friction reports and review replies from these traces, including every turn in agent lifetime traces. Text and JSON output attribute child records with agent and parent IDs; call outcomes and related IDs are resolved within each run and its initial history, without re-emitting historical reports.

`reagent friction-export --destination s3://BUCKET/PREFIX/` polls these traces immediately and every 15 minutes after each pass (`--interval` changes this; `--once` performs one pass). The default cache plus repeatable `--trace-dir`/`--trace-file` inputs backfill root/child reports and reviews, including rejected and unknown outcomes. Complete later information replaces the same deterministic `<prefix>/v1/records/<record-id>.json` object through the installed AWS CLI; there is no manifest. Derived JSON excludes raw traces and local paths, but free-form report content remains sensitive. `--dry-run` previews pending objects without AWS or state writes. Private destination-specific delivery receipts and a local lock live under the cache; only successful uploads are acknowledged, and failed/uncertain uploads are revisited next pass. Uploads time out after two minutes; SIGINT/SIGTERM stops the exporter. Source traces must survive until delivery, and each source record must have one authoritative uploader. No Git, consumer-agent, or remediation behavior is included; see README for options and failure semantics.

## Checking changes

- `make check`: `cargo fmt --check` and the offline `cargo test` suite, which never reaches the internet.
- Each tty scenario has disposable HOME and XDG cache/config.
- `make tty-check`: drives the built binary in a pseudo-terminal through `bench/tty` scenarios; run it for input or display changes.
- `make live`: opt-in live tests for providers whose key is present.
- `make git-do-eval`: opt-in repeated git_do decisions over recorded and hand-written cases; recipe mode needs no key, Jev mode needs `TYPESAFE_API_KEY`.
- `bench/` holds offline checkers for friction, behavior comparison and workflow evidence (`docs/reagent-requirement-discovery.md`, `docs/reagent-task-workflow.md`).
